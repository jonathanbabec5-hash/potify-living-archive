    BUILT TO EARN TRUST

    Proof before
    promises.

    This is a collection concept, not an open mint. Before any public release, the infrastructure, artwork, rights, eligibility, and user experience need to be verified.

    Read the build blueprint
    01

    Prove the experience

    Test one evolving asset on Solana devnet. Keep its identity consistent across stages.

    02

    Connect real evidence

    Verify Greenhouse participation and approved grow records before representing milestones as fact.

    03

    Make the rules clear

    Publish collection terms, supply, eligibility, fees, and any allowlist or snapshot rules before launch.

    04

    Test, review, then release

    Check wallet behavior, authority controls, security, and recovery on devnet before considering mainnet.

    Explore the Solana blueprint

    Candidate architecture: Metaplex Core with Core Candy Machine; a documented snapshot and Merkle allowlist if chosen; a scoped update authority; permanent metadata storage; and a public pre-reveal commitment. Real stage updates require submitted transactions. A Merkle proof establishes allowlist membership, not wallet ownership: the wallet must still authorize its claim.

    Keep collection authority in a multisig; never put private keys in the website. Before a POTIFY-paid path, verify the mint, token program, decimals, destination, and guard compatibility. Decide and test any sponsored transaction flow separately.

    Devnet acceptance: 25 test assets; eligible, ineligible, duplicate, and failed-payment cases; all twelve stage transitions; transfer continuity; interrupted-update recovery; proof verification; and wallet display.
